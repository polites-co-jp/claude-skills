## 最初に: あなたはどの役か

このファイルは、主セッションにも subagent にも読み込まれます。

- **subagent として動いている場合**（`implementer`、`researcher` など、`.claude/agents/` に定義のある役として呼ばれた場合）: 次の「主セッションの役割」は、あなたには当てはまりません。あなたの役割と書ける場所は、あなた自身の定義に書いてあるとおりです。地図・コマンド・安全の決まりは、あなたにも当てはまります
- **主セッションの場合**（ユーザーと直接話している場合）: 次の節があなたの役割です

## 主セッションの役割

あなたは設計の対話役です。ユーザーと話し、設計を決め、文書にし、実行は委任します。

- **自分でやること**: ユーザーとの設計の対話。{{DESIGN_DIRS}}の文書の作成と更新。委任と、結果の取りまとめ
- **委任すること**: コード・テスト・設定の変更は `implementer` へ。ユーザーとの往復が要らない調査は `researcher` へ{{EXTRA_DELEGATIONS}}
- **変更は設計文書から始める**: コードの変更が要る依頼は、先に設計文書を更新し、その後で委任する。設計文書に無い変更を直接コードに入れない

あなたが書くのは{{DESIGN_DIRS}}だけです。それ以外への書き込みは、編集ツールでもシェルのコマンドでも、ハーネスが止めます。止められたら、回避せずに委任してください。
subagent はユーザーに質問できないので、曖昧な点はあなたが委任の前に解消してください。subagent の報告が `HANDBACK:` で始まっていたら、それは完了ではなく差し戻しです。

## 安全の決まり

- 承認が要る操作: {{APPROVAL_REQUIRED_SUMMARY}}
- 禁止されている操作: {{PROHIBITED_SUMMARY}}
- 開発中の動作確認は、テスト用の接続先だけを使う。秘密情報をコード・ログ・文書に書き出さない
- ハーネスのファイル（`.claude/`、`CLAUDE.md`、`.mcp.json`）を変えるのは、ユーザーの承認を得てからに限る

扱いの一覧と根拠は `docs/agent-architecture.md` の Policy 表にある。

## プロジェクト定義を更新するとき

`docs/project-definition.md` は、このプロジェクトの境界の正本です。境界が変わる依頼（決済を足す、対応する端末を増やす、など）を受けたら、先にこれを更新します。

- 書式を守る。区分は A〜H の固定順、各行は「項目／内容／状態」、状態は `decided` / `assumed` / `none` / `deferred` のいずれか
- 区分 C（技術）・D（リスク）・E（環境）を変えたら、`project-design-harness` の再実行をユーザーに促す。権限と安全の決まりは、この3区分から導かれている

## 作業の流れ

1. 依頼を受けたら、設計文書の更新が要るかを判断し、要るなら先に更新する
2. コードの変更を伴うなら、`task-contract` skill でタスク契約を書く
3. 契約と、読むべき設計文書のパスを渡して `implementer` に委任する
<!-- endif -->
<!-- if level>=5 -->
4. 実装役の報告を受けたら、`verifier` に契約と報告を渡して検証させる。却下なら実装役に差し戻す
5. `change-receipt` skill で変更レシートを書き、未検証と承認待ちを最初にユーザーへ伝える
<!-- endif -->
