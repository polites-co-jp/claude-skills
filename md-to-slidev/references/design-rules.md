# デザイン規則

同梱の `style.css`・`layouts/`・`components/` が実装している規則。`slides.md` を書くときはこの規則の中で部品を選ぶ。規則を変えたいときは部品を直す。

## 基本コンセプト

白を基調とした、シンプルで情報密度の高いプレゼンテーション。装飾ではなく「情報構造が明確で、図解によって理解できる」ことを優先する。

判断の優先順位: 内容の正確性 → メッセージの明確さ → 情報構造 → 図解 → レイアウト → タイポグラフィ → 色 → 装飾。

## 色

| 用途 | 値 | 変数 |
|---|---|---|
| 背景 | `#FFFFFF` | `--md-bg` |
| 基本文字色 | `#222222` | `--md-fg` |
| 薄い線（境界線・矢印） | `#B5B9BD` | `--md-line` |
| 重要な線 | `#222222` | `--md-line-strong` |
| アクセント1 Blue Gray | `#4F6D7A` | `--md-accent-1` |
| アクセント2 Muted Teal | `#5F8078` | `--md-accent-2` |
| アクセント3 Ochre | `#B08A4A` | `--md-accent-3` |

- 本文の強調に赤・青などの派手な色を使わない。強調は配置 → サイズ → 太字 → 枠 → アクセントカラー → 下線の順に検討する。色だけで重要度を表さない
- アクセントカラーは図解の中で、グループ分け・階層・視線誘導・区別に使う。「赤＝問題」「青＝正解」のような固定の意味付けをしない
- 比較で勝敗を色で示さない。`highlight` は「今話している列」を示すためだけに使う
- 薄い下地（tint）は、Group と Architecture の overlay（範囲の重ね合わせ）にだけ使う

## フォントとタイポグラフィ

- フォント: Noto Sans JP（Slidev の `fonts.sans` で Google Fonts から読む。ウェイト 400/500/700）
- 薄い Light ウェイトは使わない。装飾的なフォントも使わない

| 要素 | サイズ | ウェイト | 変数 |
|---|---|---|---|
| 表紙タイトル | 64px | Bold | `--md-size-cover` |
| セクションタイトル | 56px | Medium | `--md-size-section` |
| タイトル | 32px | Medium | `--md-size-title` |
| 結論 | 28px | Bold | `--md-size-conclusion` |
| 本文 | 22px | Regular | `--md-size-body` |
| 補足・ラベル・フッター | 18px | Regular | `--md-size-note` |

- **18px 未満の文字は使わない**。部品は最小 18px で作ってある。`slides.md` で `text-sm` のようなクラスや `font-size` を書かない
- line-height 1.5。日本語の letter-spacing は標準（タイトルだけ 0.01em）
- キャンバスは 1920×1080（`canvasWidth: 1920`）。上の px はこのキャンバス上の値。文字を大きくしたいときは `style.css` の変数を変える

## 余白

「必要最小限の余白」が方針。過剰に広げない。意味の異なるグループの間にだけ、明確な間隔を置く。

| 場所 | 値 |
|---|---|
| 左右の外側 | 48px |
| 上下の外側 | 40px |
| タイトル → 結論 | 18px |
| 結論 → 本文 | 22px |
| 本文の項目間 | 12px |
| 左の説明 → 右の図 | 36px |

内容が少ないスライドでは下が空く。それは情報の無さの表れであって、装飾やイラストで埋める理由にはならない。

## レイアウト

| layout | 用途 | 構造 |
|---|---|---|
| `md-standard` | 通常の説明スライド | 上: タイトル／結論。左: 説明。右: 図（幅 45%、`figureWidth` で変更）。左下: セクション名。右下: ページ番号 |
| `md-wide` | 全面図解、大きな比較表、コード | 上: タイトル／結論。下: 全幅の本文。フッターは同じ |
| `md-cover` | 表紙 | 中央にタイトル。`subtitle`・`author`・`date` |
| `md-section` | セクション区切り | 中央に大きなセクション名。`subtitle` は短い一文まで |
| `md-toc` | 目次 | `md-section` のタイトルを自動で並べる |

`md-standard` の右側は、スライド幅の 1/3〜1/2 を図の領域として確保する。図が無いスライドでは `::figure::` を書かなければ左の説明が全幅になる。

セクション名はフッターに自動で出る（直前の `md-section` の `title`）。特定のスライドだけ変えたいときは frontmatter に `section:` を書く。

## 文体

- 体言止め・短いフレーズ・簡潔な箇条書き
- 避ける: 「AI は大量のコードを生成することができるため、開発者の作業時間を短縮することができます。」
- 推奨: 「AI によるコード生成 → 開発時間の短縮」または「・コード生成の自動化 ・実装時間の短縮」
- 同じリストの並列な要素は、文末の形を揃える
- 「勝者」「最適」「最強」「圧倒的」のような評価語を使わない。技術や製品を無条件に礼賛する表現も使わない

## 図解の基本スタイル

- 線: 1.25px。重要な線だけ最大 2px（`strong`、`highlight`）
- 角丸: 5px
- シャドウ: 使わない
- グラデーション: 使わない
- アイコン: 装飾目的で置かない
- 図の中の文字は 22px、ラベル・補足は 18px

## 画像

基本の UI・図形・矢印・ボックス・線・ラベルは、画像ではなく同梱の部品で作る。文字を含む図解を画像にしない。この Skill は画像を生成しない。抽象的なイラスト・コンセプトビジュアルが効くと思うスライドは、文字と図だけで成立する形で作り、報告で「イラストを足すならこのスライドにこういう絵」と候補を挙げるだけにする。

## 避けること

長い文章・長い段落、18px 未満の文字、過剰な余白、過剰なカード UI、太い枠線、強いシャドウ、グラデーション、原色の多用、装飾目的のアイコン、スライドごとのデザイン変更、同じ概念を毎回別の図で表現、1スライドに複数の結論、入力にない事実の追加、比較での優劣の暗示、無条件の礼賛。

## デザインを差し替えるとき

`style.css` の変数（色・サイズ・余白）を変えれば、`slides.md` と部品の呼び出しはそのまま使える。レイアウトの構造を変えるなら `layouts/` を、図の見た目を変えるなら `components/` を直す。`slides.md` に手を入れる必要が出たら、部品の設計が漏れている印なので部品側に戻す。
