# レビュー基準

レビュー役が、レンダリングされた1ページの画像を評価するときの基準。評価するのはデザインの品質だけで、内容の正しさや文章の上手さは評価しない。

このページを「素人っぽく」「AI が作っただけ」に見せている**最大の原因**を見つけ、なぜそう見えるのか、どう直せば良くなるのかを、画像の上の具体的な場所と見え方で言うのがレビューの仕事。「もっと洗練させる」「バランスを整える」のような、直し方の分からない指摘は書かない。

## 見る順番

上から順に見る。先に全体、後で細部。細部から見始めると、小さな揃えのずればかり拾って、ページを素人っぽくしている大きな原因を見落とす。

1. **3秒の第一印象**。画像を開いて最初に目が行く場所、次に行く場所を書き留める。それが、このページで一番伝えたいはずのもの（多くはタイトルか主張、主役の図）と一致しているか
2. **目を細めて見る**。文字を読まずに、要素を濃淡の塊として見る。塊がどこにあり、どれが重く、空きがどこに偏っているか。バランスと余白の偏りはここで分かる
3. **構造線を引く**。要素の左端・右端・上端・中心線を頭の中で縦横に引く。何本の線で揃っているか。揃っていない端はどれか
4. **まとまりを見る**。関係の深い要素どうしが近く、関係の薄い要素とは離れているか（近接）。グループ内の間隔が、グループ間の間隔より狭いか
5. **文字を読む**。タイトルから順に読み、改行位置、サイズの差、太さ、行の長さ、行間を見る
6. **量を見る**。読み切るのにかかる時間と、画面の広さが釣り合っているか
7. **一つずつ外してみる**。枠、線、色、背景、アイコン、画像のそれぞれについて「これを取ったら何が失われるか」を考える。何も失われないなら装飾
8. **まとめる**。1〜7で見つけた問題のうち、第一印象を一番悪くしているものはどれか

## 評価の観点

### Visual hierarchy（視覚的な階層）

見た瞬間に、何を最初に見て、次に何を見ればよいかが分かるか。

- 入口が1つあるか。最初に目が行く場所が無い（全部が同じ強さ）、または2つ以上ある（大きな図と太字の文章が張り合う）のは問題
- タイトル・主張・本文・補足の順に、見た目の強さが下がっているか。強さはサイズ・太さ・色の濃さ・位置・周りの余白で決まる
- サイズの差（ジャンプ率）が足りているか。タイトルと本文の大きさが近いと、どこから読むか迷う。目安として、タイトルは本文の1.4倍以上、階層が3段なら段ごとにはっきり差がある
- 強調が多すぎないか。太字・色・枠が1ページに何か所もあると、強調が強調として働かない。強調は1ページに1か所が基本
- 主張（結論）がある場合、それが本文の中に埋もれていないか

### Layout（配置）

要素の位置に意図があり、見えない格子に沿って並んでいるか。

- 左端の揃え: 本文・図・キャプションの左端が、少ない本数の縦の線に揃っているか。数 px〜十数 px だけずれた左端が複数あるのは、揃っていないより悪く見える（意図のない微妙なずれ）
- 上端の揃え: 2カラムのとき、左右の塊の上端（または中心）が揃っているか
- 中央揃えの使い方: 表紙・区切り・1文だけのページ以外で、複数行の本文を中央揃えにしていないか。行頭が揃わず読みにくい
- 要素の大きさの意味: 大きい要素ほど重要に見える。重要でない要素（補足の図、ロゴ）が大きすぎないか。主役の図が小さすぎて隅に置かれていないか
- 塊の数: 1ページの独立した塊は3〜4個まで。それを超えると散らかって見える
- 画面端: 要素が画面端に近すぎないか（外周の余白が内側の間隔より狭いと窮屈に見える）
- 同じ役割の要素（並んだ箱、列）の大きさと間隔が揃っているか

### Whitespace（余白）

余白が、まとまりを示す道具として働いているか。

- 近接: グループ内の間隔 < グループ間の間隔 < 外周の余白、の順になっているか。どこも同じ間隔だと、まとまりが見えない
- 偏り: 空きが一か所に固まっていないか。典型は「内容が上 1/3 に詰まり、下 2/3 が空いている」上詰め。これは余白ではなく、配置が決まっていない状態に見える
- 詰まり: 要素どうし、要素と枠の間が詰まりすぎていないか。枠の内側の余白が、文字の高さより狭いと窮屈に見える
- 余白の量と内容の量が釣り合っているか。内容が少ないのに小さく描き、周りがただ空いているのは、「余白を取った」ではなく「スケールを決めていない」

### Typography（文字組み）

- 改行位置: タイトルや主張が、語の途中・助詞の直前・数字と単位の間で折り返していないか。最後の行に1〜3文字だけ残る（泣き別れ）のは目立つ。日本語では、意味の切れ目（文節）で改行する
- 行頭の約物: 句読点・閉じ括弧・長音が行頭に来ていないか
- 行の長さ: 本文1行が長すぎないか（日本語で1行 35〜40 字を超えると読みにくい）。逆に図の横で数文字ずつ折り返していないか
- 行間: 本文の行間が詰まりすぎ・空きすぎていないか（目安は文字サイズの 1.4〜1.7 倍）。見出しは本文より詰める
- ウェイト: 太さの種類が多すぎないか（2〜3種類まで）。細すぎる文字が背景に負けていないか
- サイズの種類: 1ページで使う文字サイズが多すぎないか（4種類程度まで）。似たサイズ（22px と 24px のような）が混ざると、差が意図に見えない
- 和欧の混在: 英数字が和文から浮いていないか（別のフォントで太さや高さが違う）。半角と全角の数字・記号が混ざっていないか
- 読める大きさ: 投影したときに後ろの席から読めない小さな文字が無いか。キャンバス 1920×1080 なら 18px 程度が下限の目安

### Density（情報密度）

- 詰め込み: 読むのに30秒以上かかる文章量、箇条書きの入れ子が深い、1ページに図が2つ以上、など。聴衆は話を聞きながら読むので、読み切れない量は伝わらない
- 間延び: 内容が少ないのに画面の一部しか使っていない。内容を増やすのではなく、内容の大きさと配置で画面を使う（主役を大きくする、1文を大きく置く）
- 箇条書きだけのページ: 図にできる関係（順序・比較・構成）が箇条書きで並んでいないか。これはデザインの問題として指摘してよい（直し方は図にするか、並びで関係を見せる）

### Visual balance（視覚的な重さの釣り合い）

- 目を細めたときの塊の重さが、左右・上下で釣り合っているか。完全な対称である必要はないが、意図のない偏り（片側だけ重い、全体が上に寄る、右下だけ空く）は問題
- 重さは、面積・濃さ（太字、濃い色、塗り）・複雑さで決まる。小さくても黒く塗った箱は重い
- 2カラムで、片側だけが極端に短い・小さいとき、そのカラムの幅や位置が内容に合っているか

### Visual semantics（見た目の意味）

- 図・画像・アイコン・線・枠・背景・色が、それぞれ何かを伝えているか。取っても何も失われないものは装飾
- 色の意味: 同じ色が同じ意味で使われているか。意味の無い色の違い（箱ごとに色が違うが区別に意味が無い）は、読む人に存在しない区別を探させる
- 矢印・線: 流れや関係を示しているか。線の太さ・種類・色が混在していないか
- 枠とカード: 全部の要素を枠で囲んでいないか。枠は区別が要るものだけに使う。枠が多いと、どれも同じ重さになる
- 影・グラデーション・立体効果: 情報を足していないなら、古さや素人っぽさの原因になる
- アイコン: 言葉の横に置いただけのアイコンは、意味を足さずに視線を奪う

### Professionalism（仕上がり）

そのページが「AI が生成しただけ」「PowerPoint の既定のまま」に見える原因を、具体的な見た目で特定する。次の症状が典型。

| 症状 | 見え方 | 直し方の方向 |
|---|---|---|
| 上詰め | 内容が上に寄り、下半分以上が空く | 主役を大きくする、縦方向の配置を決める（中央寄せ、上下に分ける）、図の縮尺を上げる |
| 既定の箇条書き | 黒丸の箇条書きが左上から並ぶだけ | 項目の関係（順序・対比・並列）を配置で見せる、主張を1つ大きく置く |
| 全要素が同じ強さ | どこから見ればよいか分からない | 主役を1つ決め、それ以外を小さく・薄くする |
| 微妙なずれ | 左端や上端が数 px ずつずれている | 揃える線を決めて、全要素をそこに合わせる |
| 小さな図が隅に | 図が画面の一角で小さく、周りが空く | 図を主役の大きさにする、または図の比重を下げて文字を主役にする |
| 枠だらけ | すべてが角丸の箱に入っている | 区別が要る箱だけを残し、ほかは余白でまとめる |
| 装飾の混入 | 意味の無いアイコン、影、グラデーション、背景の模様 | 外す |
| 色が多い | 3色以上に意味の違いが無い | 基本の文字色と強調色1色に減らす |
| タイトルの泣き別れ | 最後の行に1〜3文字 | 文節で改行する、文言を詰める、幅を変える |
| 全部太字 | 本文まで太く、強調が効かない | 太字を主張か1語だけにする |

## 重大度

| 重大度 | 基準 | 例 |
|---|---|---|
| Critical | ページとして成立していない。情報が読めない・壊れている | 文字がはみ出して切れている、要素が重なって読めない、背景と文字の差が小さく判読できない、投影すると読めない小ささ |
| Major | 第一印象で素人っぽさ・未完成さを与える主な原因。直すとページの印象が変わる | 上詰めで下半分が空く、入口が無い／2つある、タイトルの泣き別れ、揃っていない端が目立つ、主役の図が小さい、枠だらけ |
| Minor | 気づく人は気づく細部。直しても印象は大きく変わらない | 数 px の揃え、間隔のわずかな不統一、記号の不揃い、補足の行間 |

Critical と Major が無いページは「完成度が高い」と判定してよい。Minor が残っていてもループは終わる。

## 優先順位の付け方

- 優先順位は「直したときにページの見え方がどれだけ変わるか」で決める。重大度が同じなら、見え方の変化が大きい方が先
- Critical があれば必ず Priority 1
- Priority は最大3つ。4つ目以降は Issues の一覧に書くだけでよい
- 複数の症状が同じ原因から来ているなら、原因を1つの Priority にまとめる（例: 「上詰め」と「図が小さい」は、どちらも縦の配置が決まっていないことが原因）
- 前のレビューを知らない前提で書く。今の画像にある問題だけを書く

## 指摘の書き方

各 Priority に次を書く。

- **問題**: 何が起きているか。画像のどこか（「右半分の3つの箱」「タイトルの2行目」「下 2/3 の空き」）を必ず添える。位置は、左上・中央・右下のような9分割か、要素の名前で言う
- **なぜ問題か**: 見る人にどう見えるか、何が伝わらなくなるか。原則（近接、揃え、ジャンプ率など）の名前だけで済ませず、このページで起きていることで説明する
- **改善案**: 実装役がそのまま手を動かせる具体さで書く。「大きくする」ではなく「右の図を縦方向に広げ、画面の高さの 6 割程度を使う」、「揃える」ではなく「左カラムの本文と結論行の左端を同じ線に合わせる」。数値は目視の概算なので「約」「程度」を付ける。内容（文言の意味）を変える案は出さない。改行位置や言い回しの長さに触れるのはよい
- **直ったと分かる見え方**: 直ったあとの画像がどう見えれば解決か（「下の空きが画面の 1/4 以下になる」「最初に目が行くのが結論行になる」）

## 避けること

| 避けること | 理由 |
|---|---|
| 細部から書き始める | 大きな原因を見落とし、Minor の山ができる |
| 抽象的な指摘（「洗練させる」「メリハリをつける」） | 実装役が何をすればよいか分からず、直しても直ったか判定できない |
| 問題を大量に並べる | 実装役が優先を判断できず、全部を少しずつ直して何も良くならない |
| 内容や文章の良し悪しを評価する | この役の範囲外。文言の意味には触れない |
| 装飾や要素を足す提案を先に考える | 素人っぽさの多くは、足すことではなく、減らす・揃える・大きさを決めることで直る |
| ソースコードや前回のレビューを見て判断する | 見るのは今レンダリングされた画像だけ。前に何を指摘したかに引きずられない |
| 数値を正確な値のように書く | 画像からの目視は概算。「約 40px」のように書く |
| 良い点を空欄にする、または一般論で埋める | 良い点は、実装役が壊してはいけないものの一覧になる。具体的に書く |
