# 完成例: md-to-slidev の完成例の 7 ページ目

この Skill を実際に1ページで回したときの記録一式（2026-09-25、Slidev 53.0.0、playwright-chromium 1.63.0）。
対象は、同じリポジトリの md-to-slidev に同梱している完成例（[../../../md-to-slidev/assets/example/slides.md](../../../md-to-slidev/assets/example/slides.md)）の 7 ページ目「自動化は一度に全部やらず、3段階で広げる」。
一時フォルダに展開したデッキで回したので、md-to-slidev 本体の部品は変えていない。

読む順:

1. [page-07/log.md](page-07/log.md): 経過表。各回に何を問題とし、何を変え、比較でどう判定されたか
2. `review-k.md`: レビュー役の出力（毎回新しい subagent が、その時点の画像だけを見て書いた）
3. `changes-k.md` と `diff-k.patch`: 実装役の変更記録と、実際の差分
4. `compare-k.md`: 比較役の判定（新旧を伏せた A/B で、どちらが新しかったかは進行役が記録）
5. [patterns.md](patterns.md): ページをまたいで貯める症状の記録と、共通化の候補

この例で見えたこと:

- 3回とも、全ページの画素比較で変化は 7 ページ目だけだった。実装役は共通のファイル（`components/Step.vue`・`style.css` など）に手を入れたが、新しい props や frontmatter を指定したページにだけ効く形にした
- レビュー 1〜3 のすべてで「タイトルが主張行より弱い」が挙がった。原因は layout の既定の文字組みで、md-standard・md-wide の全ページに同じ構造がある。実装役は全ページを変えずに 7 ページ目だけを直し、デッキ全体で揃えるかを提案として残した（`patterns.md` の共通化の候補）
- 最後のレビューの Priority 2 は、修正 2 で詰めた箱の高さを再び広げる向きだった。上限の 3 回で止めたので、指摘の往復に入る前に終わった
