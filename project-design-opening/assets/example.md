# Project Definition: 小規模店舗向け予約管理サービス

## A. 目的とスコープ

| 項目 | 内容 | 状態 |
|---|---|---|
| 目的 | 美容室や整体院のような小規模店舗が、電話に出られない時間帯の予約の取りこぼしを無くす。来店客が Web から予約と事前決済を行い、店舗側は予約の一覧を管理できる | decided |
| やること | 来店客向けの予約受付 | decided |
| やること | 店舗向けの予約管理画面 | decided |
| やること | 事前決済 | decided |
| やること | 予約確認の通知 | assumed |
| やらないこと | モバイルアプリは作らない。Web だけで提供する | decided |
| やらないこと | 複数店舗をまたぐチェーン向けの機能 | assumed |
| 制約 | 最初の導入先は知人の店舗1軒。3か月以内に実際に使い始めたい | decided |

## B. システム境界

| 項目 | 内容 | 状態 |
|---|---|---|
| 利用者との接点 | 来店客向けの Web 画面 | decided |
| 利用者との接点 | 店舗向けの管理画面（Web） | decided |
| 処理 | サーバー側で予約の受付と管理を行う | assumed |
| データの保存先 | DB に店舗・予約・来店客の情報を保存する | assumed |
| 外部とのやりとり | 決済サービス（カード決済の課金と返金） | decided |
| 外部とのやりとり | メール送信サービス（予約確認と前日の通知） | assumed |
| 利用者の識別（認証） | 店舗側はログインが必要。来店客はログインなしで予約できる | decided |
| 配布・実行場所 | クラウド上で動かす | assumed |

```text
来店客向け Web 画面 ─┐
                     ├→ アプリケーションサーバー → DB
店舗向け管理画面   ──┘         │
                               ├→ 決済サービス（外部）
                               └→ メール送信サービス（外部）
配布・実行場所: クラウド
```

## C. 技術

| 項目 | 内容 | 状態 |
|---|---|---|
| 言語 | TypeScript | assumed |
| ランタイム | Node.js | assumed |
| パッケージマネージャ | pnpm | assumed |
| 主要フレームワーク | Next.js | assumed |
| DB 種別 | PostgreSQL | assumed |
| デプロイ先種別 | コンテナを動かせるクラウド | assumed |

## D. リスク

| 項目 | 内容 | 状態 |
|---|---|---|
| 外部作用 | 決済サービスへの課金と返金の依頼。実際にお金が動く | decided |
| 外部作用 | 予約確認メールの送信。実在の来店客に届く | assumed |
| 外部作用 | クラウドへのデプロイ | assumed |
| 不可逆・機微な操作 | 本番 DB のマイグレーションとデータ削除 | assumed |
| 秘密情報・個人情報 | 秘密情報: 決済サービスとメール送信サービスの API キー、DB の接続情報 | assumed |
| 秘密情報・個人情報 | 個人情報: 来店客の氏名・メールアドレス・電話番号。カード番号は自前で保持せず決済サービスに任せる | decided |
